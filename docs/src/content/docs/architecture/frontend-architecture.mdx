## State Management

FLONP uses minimal state management. No Redux or Zustand required.

| State | Type | Initial | Description |
|-------|------|---------|-------------|
| `result` | `FormulationResult \| null` | `null` | API response data |
| `error` | `string \| null` | `null` | Error message to display |
| `isLoading` | `boolean` | `false` | Loading state during API call |

Form state is managed internally by React Hook Form.

### State Location

| State | Location | Manager |
|-------|----------|---------|
| Form values | `FormulationForm` | React Hook Form |
| Form errors | `FormulationForm` | React Hook Form + Zod |
| Loading state | `App` | `useState` |
| API result | `App` | `useState` |
| API error | `App` | `useState` |

### State Flow
```
┌─────────────────────────────────────────────────────────────────┐
│                         App.tsx                                 │
│                                                                 │
│   const [result, setResult] = useState<FormulationResult | null>│
│   const [error, setError] = useState<string | null>             │
│   const [isLoading, setIsLoading] = useState(false)             │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                  FormulationForm                        │   │
│   │                                                         │   │
│   │   Form state managed by React Hook Form                 │   │
│   │   Validation managed by Zod                             │   │
│   │                                                         │   │
│   │   onSubmit={(data) => {                                 │   │
│   │     setIsLoading(true)                                  │   │
│   │     optimizeFormulation(data)                           │   │
│   │       .then(setResult)                                  │   │
│   │       .catch(setError)                                  │   │
│   │       .finally(() => setIsLoading(false))               │   │
│   │   }}                                                    │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│   {isLoading && <LoadingSpinner />}                             │
│   {error && <ErrorDisplay message={error} />}                   │
│   {result && <ResultsCard result={result} />}                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## Component Specifications

### App.tsx

**Purpose:** Root component that orchestrates application state and layout.

**Location:** `src/App.tsx`

**State:**

| State | Type | Initial | Description |
|-------|------|---------|-------------|
| `result` | `FormulationResult \| null` | `null` | API response data |
| `error` | `string \| null` | `null` | Error message to display |
| `isLoading` | `boolean` | `false` | Loading state during API call |

**Behavior:**
- Renders `Header`, `FormulationForm`, and conditionally renders `LoadingSpinner`, `ErrorDisplay`, or `ResultsCard`
- Passes `handleSubmit` callback to `FormulationForm`
- Clears previous result/error when new submission starts
- Catches API errors and sets appropriate error message

**Dependencies:**
- All child components
- `optimizeFormulation` from `lib/api.ts`

---

### Component: FormulationForm.tsx

**Purpose:** Three-section form for collecting formulation parameters.

**Location:** `src/components/FormulationForm.tsx`

**Props:**

| Prop | Type | Required | Description |
|------|------|----------|-------------|
| `onSubmit` | `(data: FormulationInput) => void` | Yes | Callback when form is valid and submitted |
| `isLoading` | `boolean` | Yes | Disables form during API call |

**Form Fields:**

| Section | Field | Type | Default | Validation |
|---------|-------|------|---------|------------|
| Organic Phase | Lipid Composition | Select | Empty (placeholder) | Required, enum |
| Organic Phase | Lipid Concentration | Number input | Empty | 10.0–50.0 mM |
| Organic Phase | Solvent | Disabled input | "Ethanol 99%" | Fixed value |
| Aqueous Phase | Payload Type | Select | Empty (placeholder) | Required, enum |
| Aqueous Phase | Payload Concentration | Number input | Empty | 0.05–1.0 mg/mL |
| Aqueous Phase | Buffer Type | Select | Empty (placeholder) | Required, enum |
| Process Target | N/P Ratio | Number input | Empty | 4–20, integer |

**Behavior:**
- Uses React Hook Form for form state management
- Uses Zod schema for validation via `@hookform/resolvers`
- Uses React Hook Form with Zod resolver for validation
- Dropdowns show placeholder text until user selects an option
- Number inputs are empty until user enters a value
- Displays inline validation errors below each field
- Disables submit button when loading or form is invalid
- Converts string inputs to numbers before submission
- Groups fields into three visual sections

**Dependencies:**
- React Hook Form
- `@hookform/resolvers/zod`
- Zod schema from `lib/schemas.ts`
- Constants from `types/formulation.ts`
- shadcn/ui: Button, Card, Input, Select, Form, Label

## Form Validation

### Zod Schema Location

`src/lib/schemas.ts`

### Validation Rules

| Field | Rules | Error Message |
|-------|-------|---------------|
| `lipidComposition` | Required, must be one of enum values | "Required" |
| `lipidConcentration` | Required, number, min 10.0, max 50.0 | "Must be between 10.0 and 50.0 mM" |
| `solventType` | Must be "Ethanol 99%" | — |
| `payloadType` | Required, must be one of enum values | "Required" |
| `payloadConcentration` | Required, number, min 0.05, max 1.0 | "Must be between 0.05 and 1.0 mg/mL" |
| `bufferType` | Required, must be one of enum values | "Required" |
| `targetNpRatio` | Required, integer, min 4, max 20 | "Must be between 4 and 20" |

### Validation Flow
```
User types in field
       │
       ▼
React Hook Form captures value
       │
       ▼
On blur or submit: Zod validates
       │
       ├─── Valid ──────▶ Clear field error
       │
       └─── Invalid ────▶ Set field error
                               │
                               ▼
                         FormMessage displays error
```

### Validation Timing

- Validation runs on blur and on submit
- Errors display inline below each field via `FormMessage` component

## API Integration

### API Client Location

`src/lib/api.ts`

### Functions

| Function | Purpose |
|----------|---------|
| `optimizeFormulation(input: FormulationInput): Promise<FormulationResult>` | Calls POST /optimize |

### Responsibilities

- Convert camelCase (frontend) to snake_case (API request)
- Convert snake_case (API response) to camelCase (frontend)
- Handle timeout (30 seconds)
- Throw `ApiRequestError` with status and message on failure

### Error Handling

| HTTP Status | Error Type | User Message |
|-------------|------------|--------------|
| 422 | Validation | "Validation error" |
| 500 | Server | "Failed to generate recommendation. Please try again." |
| 504 | Timeout | "Request timed out. Please try again." |
| Network failure | Connection | "Unable to connect to server." |

## UI Flow
```
1. User opens app
   └── Form displayed with empty fields, dropdowns show placeholders

2. User fills form
   └── Validation runs on blur, errors appear inline if invalid

3. User clicks "Calculate"
   ├── If form invalid → Show validation errors, stop
   └── If form valid → Continue

4. API call starts
   ├── isLoading = true
   ├── Previous result/error cleared
   ├── Form disabled
   └── LoadingSpinner displayed

5. API responds
   ├── Success (200) → ResultsCard displayed with data
   ├── Error (4xx/5xx) → ErrorDisplay shown with message
   └── Timeout → ErrorDisplay shown with timeout message

6. isLoading = false
   └── Form re-enabled
```
