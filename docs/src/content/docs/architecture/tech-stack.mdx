## Overview

This document defines the complete technology stack for FLONP.

The stack prioritizes: developer productivity, type safety, fast iteration, and minimal operational complexity.

---

## Frontend

| Technology | Version | Purpose | Rationale |
|------------|---------|---------|-----------|
| **React** | 19.x | UI framework | Industry standard, large ecosystem, familiarity likely |
| **Vite** | 7.2.x | Build tool | Fast HMR, modern defaults, simpler config than Webpack |
| **TypeScript** | 5.x | Type system | Catches errors at compile time, improves code documentation |
| **Tailwind CSS** | 4.x | Styling | Utility-first approach speeds up UI development, no CSS file management |
| **shadcn/ui** | latest | Component library | Pre-built accessible components, copy-paste model allows customization |
| **React Hook Form** | 7.x | Form management | Minimal re-renders, native validation integration, simple API |
| **Zod** | 4.x | Schema validation | TypeScript-first, integrates directly with React Hook Form via resolver |

### Frontend Hosting

| Service | Purpose | Rationale |
|---------|---------|-----------|
| **Netlify** (Free Tier) | Static hosting + CDN | Zero-config deploys from Git, automatic HTTPS, generous free tier |

| **Anthropic API** | — | LLM provider | Claude models |
| **claude-3-5-haiku** | latest | Model selection | Fast responses, cost-effective, sufficient reasoning for formulation logic |

### LangChain Components Used

| Component | Purpose |
|-----------|---------|
| `ChatAnthropic` | LLM client wrapper for Claude |
| `ChatPromptTemplate` | System + human prompt construction |

### Why pnpm over npm?

- Faster installs via content-addressable storage
- Stricter dependency resolution (avoids phantom dependencies)
- Disk space efficient (shared packages across projects)

### Why uv over pip?

- 10-100x faster package installation
- Built-in virtual environment management
- Drop-in replacement for pip commands
- Written in Rust, minimal dependencies

## Environment Variables

Both frontend and backend require environment configuration.

### Backend (.env)

| Variable | Description | Example |
|----------|-------------|---------|
| `ANTHROPIC_API_KEY` | Anthropic API key for Claude | `sk-ant-...` |
| `ALLOWED_ORIGINS` | CORS allowed origins (comma-separated) | `http://localhost:5173,https://flonp.netlify.app` |

### Frontend (.env)

| Variable | Description | Example |
|----------|-------------|---------|
| `VITE_API_URL` | Backend API base URL | `http://localhost:8000` (dev) or `https://flonp-api.railway.app` (prod) |

> **Security Note:** Never commit `.env` files to version control. Both `.gitignore` files must include `.env`.

> **API Key:** Each developer must create their own Anthropic account and generate an API key at https://console.anthropic.com/. See DEVELOPMENT_SETUP.md for instructions.

## What's NOT in the Stack

These technologies were considered but explicitly excluded:

| Technology | Reason for Exclusion |
|------------|----------------------|
| Next.js | SSR/SSG unnecessary for this SPA; adds complexity |
| Redux / Zustand | No complex state management needed; form state handled by React Hook Form |
| PostgreSQL / SQLite | MVP is stateless; no persistence required |
| Docker Compose | Single backend service; no orchestration needed locally |
| Jest / Pytest | Testing deferred to 3-month plan; MVP prioritizes speed |
| Axios | Native `fetch` sufficient for single endpoint |
| npm / pip | pnpm and uv are faster, stricter, and more efficient |
